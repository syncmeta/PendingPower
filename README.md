# PendingPower

[English](#english) · [中文](#中文)

---

## English

A tiny macOS menu bar app that does one thing: shows real-time system power draw in watts. `8.34 W`. That's it.

**Apple Silicon only.** Reads SoC energy counters via Apple's private `IOReport` framework — no `sudo`, no kernel extensions, no entitlements.

### Features

- Live system power (CPU + GPU + ANE + DRAM) in the menu bar, updated every second.
- Click for a per-component breakdown.
- Adaptive precision: `<10 W` shows two decimals, `10–99 W` shows one, `≥100 W` shows none — so the width stays roughly stable.
- ~120 KB single executable. No dock icon.

### Quick start

```bash
# Open in Xcode (it understands SPM packages)
open Package.swift

# Or build and run from the CLI
swift run
```

### Build a `.app` bundle

```bash
scripts/build.sh
open build/PendingPower.app
```

Without a signing identity, the script does ad-hoc signing — fine for local use.

### Sign + notarize + distributable DMG

One-time keychain setup (uses an [app-specific password](https://appleid.apple.com)):

```bash
xcrun notarytool store-credentials PendingPowerNotary \
    --apple-id "you@example.com" \
    --team-id "YOURTEAMID" \
    --password "xxxx-xxxx-xxxx-xxxx"
```

Then one command does build → sign → notarize → staple → drag-to-Applications DMG → re-notarize:

```bash
scripts/build-dmg.sh \
    --sign "Developer ID Application: Your Name (YOURTEAMID)" \
    --notary-profile PendingPowerNotary
```

Output: `build/PendingPower.dmg` — open it and you get a window where you drag the app onto Applications. Gatekeeper accepts it on any Mac.

> **Why not the Mac App Store?** App Store review rejects private API usage, and `IOReport` is private. Developer ID + notarization is the right path here.

### How it works

The app dynamically loads `/usr/lib/libIOReport.dylib` via `dlsym` and uses ten of its functions to subscribe to the `Energy Model` channel group. Each second it samples the energy counters, takes the delta from the previous sample, divides by elapsed time, and groups channels by name into CPU / GPU / ANE / Other buckets. Same approach as `asitop`, Stats.app, and macmon.

### Project layout

```
Sources/PendingPower/
  main.swift                  app entry, menu bar setup
  IOReportBridge.swift        dlsym-loaded private API
  PowerMonitor.swift          1 Hz sampler, per-channel aggregation
  StatusBarController.swift   NSStatusItem + dropdown menu
Resources/
  Info.plist                  LSUIElement = true (no Dock icon)
  Entitlements.plist          empty — Hardened Runtime, no special entitlements
  AppIcon.icns                generated by scripts/make-icon.swift
scripts/
  build.sh                    SPM build → assemble .app → codesign
  build-dmg.sh                full release pipeline
  make-icon.swift             CoreGraphics icon generator
```

### Cross-checking accuracy

```bash
sudo powermetrics --samplers cpu_power,gpu_power -i 1000 -n 3
```

Compare the `Combined Power` line to the menu bar reading — should match within ±10%.

### Caveats

- Apple Silicon only. Intel Macs would need a different code path (SMC keys).
- Uses a private framework. Apple may change it in a future macOS — historically it has been stable for many years.
- Built and tested on macOS 13+. Project's tmp build directory lives at `/tmp/PendingPower-build` to avoid iCloud Drive's file provider re-attaching `com.apple.FinderInfo` xattrs (which `codesign` rejects).

## 中文

一个超简单的 macOS 菜单栏小工具,**只做一件事**:在菜单栏实时显示整机功耗(瓦特)。`8.34 W`,就这样。

**仅 Apple Silicon。** 通过 Apple 私有的 `IOReport` 框架读取 SoC 能量计数器 —— 不用 `sudo`,不用内核扩展,不需要 entitlement。

### 功能

- 菜单栏实时显示整机功率(CPU + GPU + ANE + DRAM),每秒刷新。
- 点击展开看分组件细分。
- 精度自适应:`<10 W` 两位小数,`10–99 W` 一位小数,`≥100 W` 整数 —— 宽度基本稳定不抖。
- 约 120 KB 单可执行文件,无 Dock 图标。

### 工作原理
